# ace-mcp v3.0.0 Release Note

`ace-mcp v3.0.0` focuses on making the local code-search workflow more usable and safer in real projects, especially when queries or source code contain Unicode content.

This branch now also includes a semantic retrieval MVP on top of the `v3.0.0` release baseline, so the note below is split into the original release scope plus the latest search upgrade.

## Highlights

- Supports Unicode and Chinese query token analysis.
- Preserves valid UTF-8 during indexing to avoid garbled indexed content for Chinese source files.
- Blocks `get_file_snippet` from reading files outside the project root.
- Normalizes project root lookups for `project_stats`.
- Adds automated regression tests for query analysis, search filters, metadata mode, and snippet path safety.
- Narrows npm package contents to release-facing artifacts only.
- Adds a local semantic retrieval MVP with semantic term expansion and hybrid recall.

## Key Changes

### Search quality

- `queryAnalyzer` now keeps Unicode tokens instead of dropping them during normalization.
- Search adds a Unicode-friendly lexical fallback path for content matching.

### Indexing reliability

- Source decoding now prefers valid UTF-8 so multilingual files are indexed correctly.

### Safety

- File snippet resolution now validates that resolved paths stay under the project root.
- Project stats lookups normalize project roots before querying persisted metadata.

### Engineering quality

- Added `npm test`.
- Added focused regression tests around indexing, search, filters, metadata responses, and snippet boundaries.

## Supplement: semantic retrieval MVP

### User-facing impact

- Adds explicit `semantic` search mode.
- Enables semantic recall in `auto` and `hybrid` for natural-language style queries, while avoiding extra recall for obvious symbol/path lookups.
- Improves conceptual matching across common engineering terms such as `login/signin/auth`, `handler/controller/endpoint`, and `repository/dao/store`.

### Implementation summary

- Added local semantic term generation with:
  - identifier splitting
  - Unicode-aware normalization
  - CJK-friendly token handling
  - lightweight synonym expansion
- Added per-chunk semantic FTS storage via `chunk_semantic_fts`.
- Added semantic backfill support so older indexed chunks can participate in semantic retrieval without requiring a full reindex first.
- Integrated semantic results into search reranking and result explanations.
- Exposed `semantic` mode in:
  - MCP `search_context`
  - Web debug panel
  - README usage docs
- Added regression coverage for semantic synonym matching.
