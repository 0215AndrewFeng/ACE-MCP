# Lessons

- 2026-08-14: Root-only watchers still need a global per-process budget. One native watcher per registered project can exceed a low LaunchAgent FD limit; cap active watchers and retain eventual correctness by reporting overflow projects as periodic-only participants in startup and periodic reconciliation.
- 2026-08-14: Never delete FTS5 rows one chunk at a time through an `UNINDEXED` identifier column. SQLite cannot use that column as an index, so every DELETE scans the FTS table; batch all chunk IDs for one file into a single `IN (...)` deletion per FTS table and cover it with a scan-count regression.
- 2026-08-14: A separate lease heartbeat worker does not protect a short TTL from long SQLite write transactions. Before each independent persistence phase, wait for an in-flight heartbeat, proactively renew when the remaining TTL is below the worst-case phase budget, and fail closed if renewal or fencing fails.
- 2026-08-14: When recursive watcher `EMFILE` recovery hot-loops and maintenance lease heartbeats expire behind multi-minute SQLite writes, stabilize watcher resource usage/backoff and lease liveness before startup scheduling or concurrency benchmarking. Raising FD/TTL limits alone masks the fault, and performance evidence collected during the storm is invalid.
- 2026-08-13: User-visible search concurrency is a next-release delivery priority, not a long-term evaluation item. When a single SQLite search worker and roughly 50-project startup maintenance cause painful latency, schedule bounded parallel search execution first, bounded/foreground-aware startup maintenance second, and 8/16/32 plus during-index release gates in the same version; Qdrant remains conditional follow-up.
- 2026-08-04: Release handoff must update and verify the globally installed CLI separately from the source-tree LaunchAgent. Check `ace-mcp --version` both in an interactive NVM shell and with the base `/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin` PATH; a healthy repo-backed service does not prove the global command exists or is current.
- 2026-08-03: Long-lived logging must apply the configured level before every output, bound file size with cross-process rotation, and absorb serialization, filesystem, and stderr failures. For supervised services, disable duplicate stderr output so an EPIPE cannot recurse through uncaught-exception logging and KeepAlive restarts.
- 2026-08-03: Cross-project routing must retain mixed ASCII+CJK concepts such as `A转D`; boundary-only splitting collapses ownership signals into common one-character noise. When exact concepts are copied across repositories or appear in regression fixtures, combine exact evidence with query-matching repository-name anchors and qualified family siblings instead of treating every lexical copy as an owner.
- 2026-07-24: Replaceable worker shutdown must strongly track both live and terminating workers, including a worker retired by idle shutdown before `close()` snapshots state. Terminal close must await every existing stop promise instead of relying only on the current worker pointer or live set.
- 2026-07-24: Coordinator close is terminal, not a reversible stop. Every public entry point that can allocate a watcher, reconciliation timer, worker, or other long-lived resource must guard the same closing/closed state before allocation, while repeated `close()` remains idempotent.
- 2026-07-24: Cross-project routing must normalize corpus-size effects: cap FTS evidence per project and decay repeated evidence within a project. Coverage must come from explicit SQLite highlight matches, not truncated snippets or substring checks, which miss distant terms and confuse names such as `preorder` with `order`; bound every IPC input and evidence text before returning it.
- 2026-07-24: A replaceable worker client must bind each pending request to the worker that accepted it, make close idempotent, track both live and terminating workers, and ignore late error/exit from retired generations so an old worker cannot reject or clear replacement-worker state.
- 2026-07-24: Runtime project deletion changes automatic-maintenance ownership immediately. Refresh after successful deletion, retain pending refresh after failure, and use a monotonic refresh sequence so an older asynchronous snapshot cannot overwrite a newer topology.
- 2026-07-23: Async HNSW invalidation needs both in-memory generation/entry identity and persistent `indexVersion` plus vector-content identity. Vector count alone cannot detect same-size embedding changes, and a stale continuation must never unlink a shared final path after rename.
- 2026-07-23: Worker-owned project preparation should acquire an immediate SQLite transaction before reading existing files, then update status and return the snapshot in that transaction. A deferred transaction that reads before upgrading to a write lock can receive `SQLITE_BUSY` immediately instead of honoring `busy_timeout`.
- 2026-07-23: Startup freshness restore is fail-closed: only a `ready` project with a latest zero-failure event may be restored, and `restoreFreshnessState` itself must reject failed results so future callers cannot revive an error cache.
- 2026-07-23: Worker/coordinator shutdown must be bounded: reject new work, wait for active and queued indexes, then force-close after timeout. A non-ready project must recover with a full index, and every pending worker event must be scoped to its worker generation so late error/exit events cannot reject replacement-worker requests.
- 2026-07-22: Web route verification can use the `web-access` CDP proxy against the real LaunchAgent page. Create and close a dedicated background tab, restore any LocalStorage selection touched by candidate clicks, and wait for automatic startup catch-up to reach zero active indexes before judging the Web request timeout path.
- 2026-07-22: Automatic project routing is a `4.10.2` patch release. Do not infer a minor-version bump from feature scope when the repository owner has assigned the release line explicitly.
- 2026-07-21: Automatic indexing needs per-project watcher/timer state plus a change generation. An index may clear dirty only when the same watcher generation is still current; otherwise enqueue a follow-up pass after the active project index.
- 2026-07-21: Startup index catch-up must use the complete registered-project list and remain independent of recursive `fs.watch` support. File events provide low latency, while sequential reconciliation provides eventual consistency on unsupported platforms and across downtime.
- 2026-07-21: Filter watcher noise using indexed extensions and simple excluded directory names, but retain null filenames, rename events, and Git/project control files as reconciliation signals so filtering cannot hide structural changes.
- 2026-07-21: Automatic project maintenance must have one process owner. In this installation the explicit `--web-port` Web/LaunchAgent runtime owns watchers and reconciliation; stdio MCP children only index on demand, otherwise multiple clients contend on the shared SQLite database and can starve HTTP health checks.
- 2026-07-21: Enforce the automatic-maintenance owner at every watcher creation path. Guarding only the process entrypoint is insufficient if a successful explicit index can start a watcher from inside `IndexCoordinator`.

- 2026-06-24: `tasks/` was absent at the start of the v4.7.0 work. Create and maintain `tasks/todo.md` and `tasks/lessons.md` before implementation when the project instructions require task tracking.
- 2026-06-24: For worker-thread changes in this NodeNext/tsx project, verify both source (`node --import tsx`) and built dist paths. Source tests may need an IPC child process because Worker plus Node 24's native TS strip does not handle project TS syntax like parameter properties reliably.
- 2026-06-24: Long-lived workers must have an explicit close path or idle shutdown. Otherwise one-shot commands/tests can pass assertions but keep the process alive.
- 2026-06-24: Release handoff is not complete until the local running service process is replaced and both the branch commit and version tag are pushed.
- 2026-06-24: Release benchmark smoke must isolate its HOME-derived `.ace-mcp` data/log directories, surface child stdout/stderr plus `.ace-mcp/log`, and disable one-shot auto-watch. Otherwise release failures can appear as ECONNRESET while the real cause is hidden in the child process.
- 2026-06-24: Web search responses use the standard response envelope (`data.results`), so benchmark tooling must read enveloped results and assert non-empty smoke output. A p95 number with `resultCount: 0` is not a valid search benchmark.
- 2026-06-24: SQLite PRAGMAs that affect locking (`busy_timeout`, WAL, `synchronous`) must be configured in the SQLiteStore constructor, not only initialize(), because worker read connections construct their own store and may not run schema initialization first.
- 2026-06-24: `/health` must never perform per-project SQLite stats reads. Keep it to runtime, lightweight project-list fields, and in-flight index state; deep aggregate counts belong on slower project detail endpoints.
- 2026-06-24: When attaching cleanup with `promise.finally()` to an index operation that may reject, always handle the derived Promise. Otherwise the original caller may catch the error but the cleanup branch can still emit an unhandled rejection.
- 2026-06-24: When fixing one language's call graph resolution, keep both producer and consumer changes language-scoped and add a non-target-language guard test. Generic resolver score changes can silently perturb Java/Python/.NET results unless guarded by `language`.
- 2026-06-25: Adapter interface methods such as `analyzeSource` can be optional even when a specific adapter implements them. Adapter unit tests should use a non-null assertion or call through the public `analyzeSource` wrapper, then run `npm run build` after GREEN tests to catch TS-only issues.
- 2026-06-25: Markdown code-block usages should not set `ownerSymbol` unless intentionally adding docs to call graph traversal. Leaving owner empty lets `find_references` recall docs while preventing documentation sections from appearing as code callers.
- 2026-06-25: Gitee release attachment upload through CDP must target the real `#releaseDropzone` instance. Setting files on the editor upload modal input only shows a stuck modal queue; setting `.dz-hidden-input` and calling `document.querySelector("#releaseDropzone").dropzone.processQueue()` produces attach IDs for the release form.
- 2026-06-25: After creating a Gitee Release, verify the edit page as well as the detail page. The detail page may omit release description text from `innerText` even when `release[description]` is saved and visible in the edit form.
- 2026-06-25: For Vue/Svelte SFC support, do not feed the whole component file to TypeScript. TS can accidentally parse function-looking text from `<style>`/template content; mask non-script characters while preserving newlines and analyze only `<script>` blocks.
- 2026-06-25: Regex indices in JavaScript strings are UTF-16 code-unit offsets. When building an equal-length masked source for line mapping, use `content.split("")` rather than `[...content]` so assignments by regex index stay aligned if non-BMP characters appear before a script block.
- 2026-06-26: Future version tasks are not done at commit/tag/push. Automatically include release handoff before final response: create or verify the Gitee Release assets, verify download links, replace the local `:8787` service, record handoff results in `tasks/todo.md`, and push the handoff docs.
- 2026-06-26: Real Vue 2 projects often use directive modifiers (`@click.stop`, `@keyup.enter`) and lowercase registered component tags (`<hamburger>` for `Hamburger`). SFC template usage extraction must cover both, not only bare `@event` attributes and PascalCase tags.
- 2026-06-26: Template-derived Vue/Svelte usages should stay ownerless. This lets `find_references` recall template events/components while preventing `find_callers` from treating markup lines as executable caller edges.
- 2026-06-26: Release package content checks must assert each required artifact explicitly. A broad `rg "a|b|c"` over `unzip -l` can pass when only one expected file is present, so add package-manifest tests for staging lists when release docs mention packaged scripts.
- 2026-06-26: When changing shared numeric bounds, grep for old literal expectations in helper tests as well as request/schema tests. Use shared constants in generic normalizer tests, and keep one focused contract test that asserts the intended literal value.
- 2026-06-29: Real-project smoke tests that use `loadSettings()` can inherit an older user config. For language-extension features, explicitly set `textExtensions` in the smoke harness or the validation may silently skip the target files.
- 2026-06-29: For Web advanced controls, verify the full path from input element to request parsing to runtime effect. A button/input can exist and still be cosmetic if its value is never sent or consumed.
- 2026-06-29: The local `:8787` service may be managed by LaunchAgent `com.ace-mcp.server` with `KeepAlive`. For release handoff, restart the LaunchAgent (`launchctl kickstart -k gui/<uid>/com.ace-mcp.server`) instead of manually starting `node`, otherwise the old process can respawn and a sandboxed manual start may fail to write `~/.ace-mcp/data/index.db`.
- 2026-06-29: This project uses an explicit `npm test` file list. Whenever adding a new `*.test.ts`, update `package.json` and add a package-manifest assertion so full release checks actually execute the new test.
- 2026-06-30: For ace-mcp all-project maintenance, never enqueue many full indexes or summaries at once. Process one concrete project at a time, skip aggregate parent directories unless explicitly requested, verify with project stats plus `.ace-mcp/summaries/project-summary.json`, and prefer long-timeout `curl` over Node `fetch` for summary generation because client-side fetch failures can occur while the server continues work.
- 2026-06-30: Parent-directory index guards should only block aggregate roots with multiple registered child projects. A normal multi-module project may have one nested registered Web/app root and should still be processed by default.
- 2026-06-30: For long-running Web work, do not only wrap the final slow operation in a task. The whole path that can block the request, including `ensureFreshIndex`, must run inside the background task so clients receive `taskId` quickly.
- 2026-06-30: When converting a Web endpoint to async task submission, update every caller shape in the same release. Frontend and maintenance scripts may read previous synchronous `stats.indexSync` fields, so they must also handle `task.result` before release validation.
- 2026-07-01: Before release commits, inspect both staged and unstaged status. Pre-existing staged local hygiene changes such as `.gitignore` entries should be unstaged and left in the worktree unless they are part of the requested version scope.
- 2026-07-01: Canceling in-memory long tasks is cooperative unless the underlying work supports abort signals. The tracker must treat `canceled` as terminal and ignore later promise resolution/rejection, or canceled tasks can silently flip to succeeded/failed.
- 2026-07-01: For repeatable Gitee releases, prefer token-based OpenAPI publishing with local tag/artifact preflight and post-upload asset verification. Keep the CDP release-page upload path as a fallback only when `GITEE_TOKEN` is unavailable.
- 2026-07-01: World Cup knockout score analysis should separate 90-minute result from advancement, list total goals for each candidate score, and cross-check scores against the market total. When a favorite has compressed draw odds plus under support, elevate 1-1/0-0 extra-time or penalty-upset branches instead of treating them as token hedges.
- 2026-07-01: When checking whether a secret exists in Keychain or env, capture the command exit code immediately. Do not run `printf` or another command before inspecting `$?`, or missing secrets can be reported as present.
- 2026-07-01: Secret-scan tests must never embed a real token literal, even in `doesNotMatch` assertions. Use dummy sentinel values so the test itself cannot become the leak.
- 2026-07-02: Web route tests that use `createTestProjectEnvironment` should assert indexed behavior from files covered by `textExtensions`. Do not assume `.json` files are indexed, and avoid binding assertions to adapter-internal language names when only language distribution is under test.
- 2026-07-02: Web rendering tests should cover HTML attribute contexts separately from text-node contexts. `escapeHtml()` via textContent is not enough for attributes because quotes can break `title="..."`; add attribute-specific escaping and a render test with quote-bearing input.
- 2026-07-02: Web UI interaction releases should include at least one behavior-level DOM/event contract for the new control path. Static source-string checks are useful for packaging contracts, but preset/button/clipboard flows need an event-chain test to catch broken binding or scope regressions.
- 2026-07-03: VM fake DOM tests must still satisfy TypeScript build checks. When tests override helper element methods such as `querySelectorAll`, give the fake method a compatible parameter and return type instead of relying on `never[]` inference that can pass `tsx --test` but fail `tsc`.
- 2026-07-10: `/health` `PROJECT_PATH_MISSING` warnings come from registered project rows. `clear_project_index` only clears indexed files/chunks and leaves the row, so missing-path repair needs the project removal API (`DELETE /api/projects`) or store-level `deleteProject`.
